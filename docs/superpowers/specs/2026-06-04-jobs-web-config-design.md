# Jobs 模块 Web 配置台设计稿

日期：2026-06-04  
范围：本地 Web 控制台中的 Jobs 模块升级为“可配置任务中心”

---

## 1. 背景

当前 Jobs 模块已经具备：
- 任务列表展示（基于 `jobs.yaml`）
- 启停、手动运行、Reload

但它仍偏“运维面板”，还不是一个真正的“任务配置台”。  
用户希望 Jobs 模块支持：
- 在 Web 页面中配置任务
- 有任务列表
- 点击进入任务详情
- 支持新建/编辑/删除/启停/手动运行
- 参数编辑既要有基础表单，也要有 JSON 高级模式

---

## 2. 目标 / 非目标

### 2.1 目标
- Jobs 模块升级为完整 Web 配置台
- 提供：
  - 任务列表页
  - 任务详情页
  - 快速编辑抽屉
  - 高级编辑页
- 支持操作：
  - 新建
  - 编辑
  - 删除
  - 启停
  - 手动运行
- 保存最近 **1 次运行记录**，并**落盘保存**
- 参数编辑支持：
  - 表单模式
  - JSON 高级模式

### 2.2 非目标（v1）
- 不做最近 10 次运行记录
- 不做 cron 可视化构建器
- 不做复杂 schema 自动表单渲染
- 不扩展到 `api_poll/api_write` 之外的新任务类型

---

## 3. 页面结构

### 3.1 Jobs 列表页
用途：全局查看与管理任务。

展示字段：
- 任务名
- 任务类型
- cron
- enabled
- 下次运行时间
- 最近一次运行结果
- 最近一次运行时间

支持操作：
- 搜索
- 按类型筛选
- 按启用状态筛选
- 新建任务
- 手动运行
- 启停
- 进入详情页

### 3.2 任务详情页
用途：查看单任务的完整信息。

分区：
- **基础信息**：name / type / cron / enabled
- **参数摘要**：params / safety 关键信息
- **最近一次运行摘要**：last_run / ok / duration_ms / error
- **操作区**：快速编辑 / 高级编辑 / 启停 / 手动运行 / 删除

### 3.3 快速编辑抽屉
用途：修改常用字段，不离开详情页。

支持字段：
- name
- type
- cron
- enabled
- 常见 params
- 常见 safety

### 3.4 高级编辑页
用途：处理复杂参数与完整任务对象编辑。

模式：
- **表单模式**
- **JSON 高级模式**

适合：
- 粘贴完整任务 JSON
- 编辑复杂 `params` / `safety`
- 做更细粒度的高级配置

---

## 4. 数据存储设计

### 4.1 jobs.yaml
继续作为任务定义的唯一配置源。

### 4.2 新增 job-runs.json
用于落盘保存“最近 1 次运行记录”，便于服务重启后仍可展示任务最后状态。

建议结构：
```json
{
  "version": 1,
  "items": {
    "users-sync": {
      "last_run": "2026-06-04T19:30:00+08:00",
      "ok": true,
      "duration_ms": 321,
      "error": ""
    },
    "policy-write": {
      "last_run": "2026-06-04T18:00:00+08:00",
      "ok": false,
      "duration_ms": 812,
      "error": "preview confirmation required"
    }
  }
}
```

说明：
- key 为 job name
- 每个任务只保存最近 1 次执行结果

## 5. 后端 API 设计

### 5.1 列表与详情
- `GET /api/v1/jobs`
  - 返回任务列表 + 最近一次运行摘要

- `GET /api/v1/jobs/{name}`
  - 返回单任务详情：
    - 基础字段
    - params
    - safety
    - 最近一次运行记录

### 5.2 配置操作
- `POST /api/v1/jobs`
  - 新建任务

- `PUT /api/v1/jobs/{name}`
  - 更新任务

- `DELETE /api/v1/jobs/{name}`
  - 删除任务

### 5.3 执行与状态
- `POST /api/v1/jobs/{name}/run`
  - 手动运行一次

- `POST /api/v1/jobs/{name}/enable`
- `POST /api/v1/jobs/{name}/disable`

### 5.4 配置变更生效
- 新建 / 编辑 / 删除任务后：
  - 写回 `jobs.yaml`
  - 调用 `runner.Reload()`

### 5.5 运行记录落盘
- 每次任务执行结束后：
  - 更新内存状态
  - 同步写入 `job-runs.json`

## 6. 前端交互设计

### 6.1 列表页
- 表格形式展示
- 行点击进入详情
- 顶部提供：
  - 搜索框
  - 类型筛选
  - 启用状态筛选
  - 新建按钮

### 6.2 详情页
- 采用信息卡片布局，而不是只显示原始 JSON
- 最近一次运行结果单独高亮卡片展示

### 6.3 快速编辑抽屉
- 从详情页触发
- 保存后停留在详情页
- 局部刷新任务信息

### 6.4 高级编辑页
- 模式切换：
  - 表单模式
  - JSON 模式
- JSON 模式提交前必须做格式校验
- 校验失败时阻止保存并显示错误信息

---

## 7. 校验规则

### 7.1 基础校验
- `name` 必填且唯一
- `cron` 必填，且必须为 **6 段秒级表达式**
- `type` 仅允许：
  - `api_poll`
  - `api_write`

### 7.2 写入类任务约束
- `api_write` 沿用现有安全规则
- 若需要 preview 确认，则未确认前不可直接启用执行

---

## 8. v1 范围边界

### 本轮必须实现
- 列表页
- 详情页
- 快速编辑抽屉
- 高级编辑页
- 新建 / 编辑 / 删除 / 启停 / 手动运行
- 最近 1 次运行记录落盘
- 表单 + JSON 双模式

### 本轮不实现
- 最近 10 次运行历史
- cron 可视化编辑器
- 自动 schema 驱动表单
- 更复杂任务类型扩展

---

## 9. 验收标准（DoD）

1. Jobs 页面可直接新建任务并写入 `jobs.yaml`  
2. 点击任务可进入详情页  
3. 详情页可打开快速编辑抽屉与高级编辑页  
4. 支持删除、启停、手动运行  
5. 最近 1 次运行记录会写入 `job-runs.json`，服务重启后仍可显示  
6. JSON 模式保存前有格式校验  
7. 仅支持 `api_poll` / `api_write` 两种任务类型，且写入类任务遵循现有安全约束
