# 2026-06-05 — 飞连API任务页改为“任务列表 + 任务定义”设计说明

## 1. 背景

当前 `飞连API任务` 页面在完成“模板列表”拆分之后，左侧保留的是一张 `模板入口` 提示卡。  
这比之前更清晰，但还没有真正承载 `飞连API任务` 这一页面的核心职责。

从使用路径上看，进入 `飞连API任务` 页的用户真正关心的不是模板，而是：

- 查看已保存的飞连 API 任务草稿
- 快速选中并编辑某条任务
- 对已有任务做测试
- 基于任务创建周期任务
- 删除不再需要的任务

因此本次设计将删除 `模板入口` 卡片，并在同一位置改为 `任务列表`，形成标准的：

- 左侧任务列表
- 右侧任务定义工作台

布局。

---

## 2. 目标

本次改版目标如下：

1. 删除 `飞连API任务` 页中的 `模板入口`
2. 在同一位置新增 `任务列表`
3. 任务列表展示已保存的 `task-drafts`
4. 每条任务支持以下动作：
   - `测试`
   - `创建周期任务`
   - `编辑`
   - `删除`
5. 右侧继续保留现有 `飞连API任务定义` 工作台
6. `创建周期任务` 时自动跳转到 `飞连周期任务 -> 新建调度`，并预填当前任务信息

---

## 3. 非目标

本轮不做以下事情：

- 不新增新的存储模型
- 不重做任务草稿数据结构
- 不改变 `task-drafts`、`job-schedules` 后端接口协议
- 不把任务定义页改成抽屉模式或多标签页模式
- 不把模板列表重新并回任务定义页

---

## 4. 页面职责调整

## 4.1 模板列表页

模板列表页继续承担：

- 模板浏览
- 模板测试
- 模板编辑
- 模板删除
- 从模板创建任务

换句话说：

- 模板相关能力都留在 `模板列表`

## 4.2 飞连API任务页

飞连API任务页改为承担：

- 任务草稿列表
- 当前任务编辑
- 当前任务测试
- 保存任务草稿
- 从任务创建周期任务

换句话说：

- 任务相关能力都集中在 `飞连API任务`

---

## 5. 布局方案

采用你确认的 **方案 A**：

- 左侧：任务列表
- 右侧：任务定义工作台

## 5.1 左侧任务列表

左侧替换掉原先的 `模板入口` 卡片，改为任务列表区域。

建议包含：

- 顶部标题：`任务列表`
- 搜索框：按 `id / 名称 / template_id` 搜索
- 刷新按钮
- 列表项

每个列表项展示：

- 任务名称
- 任务 ID
- mode
- template_id

每个列表项提供 4 个动作：

1. `测试`
2. `创建周期任务`
3. `编辑`
4. `删除`

## 5.2 右侧任务定义工作台

右侧保留当前已有结构，不做推翻：

- 任务基础信息
- 请求配置
- 处理与输出
- 执行输出
- 顶部操作按钮：
  - `Preview`
  - `Execute`
  - `保存为任务草稿`

右侧工作台的角色定义为：

- 当左侧未选中任务时：用于创建新任务
- 当左侧选中某任务并点击 `编辑` 时：用于编辑该任务

---

## 6. 核心交互设计

## 6.1 编辑

点击左侧列表的 `编辑`：

- 加载该 `task-draft`
- 将其数据回填到右侧工作台
- 右侧进入“编辑已有任务”状态

## 6.2 测试

点击左侧列表的 `测试`：

- 使用该 `task-draft` 对应配置执行一次
- 结果写入右侧 `执行输出`
- 页面自动滚动/聚焦到输出区

这样用户不需要先手工点 `编辑` 再点 `Execute`。

## 6.3 删除

点击左侧列表的 `删除`：

- 二次确认
- 删除该 `task-draft`
- 若右侧当前加载的是同一条任务，则右侧回到新建态

## 6.4 创建周期任务

点击左侧列表的 `创建周期任务`：

- 跳转到 `飞连周期任务`
- 进入 `新建调度` 场景
- 自动预填以下字段：
  - `target_type = task_draft`
  - `target_id = 当前任务草稿 id`
  - 可选预填 `任务名称`

用户只需要继续补：

- cron / interval
- 启用状态
- 生效时间范围

这比“一键直接创建默认调度”更稳妥，也更符合你刚才确认的交互。

---

## 7. 数据来源与后端依赖

本设计复用现有接口，不需要新增核心后端协议。

已确认存在的接口包括：

- `GET /api/v1/task-drafts`
- `GET /api/v1/task-drafts/{id}`
- `POST /api/v1/task-drafts`
- `PUT /api/v1/task-drafts/{id}`
- `DELETE /api/v1/task-drafts/{id}`

以及周期任务接口：

- `GET /api/v1/job-schedules`
- `POST /api/v1/job-schedules`
- `PUT /api/v1/job-schedules/{id}`

因此本轮重点是：

- 前端布局与交互重组
- 任务列表与编辑器之间的数据联动
- 跳转到周期任务页时的预填行为

---

## 8. 推荐实现方式

## 8.1 任务列表容器

直接复用现有 `task-drafts` 数据获取能力与缓存：

- `refreshTaskDrafts()`
- `window.__taskDraftCache`

将原本位于右侧或底部的 `已保存任务草稿` 改造成左侧主列表。

## 8.2 任务列表动作

左侧列表项按钮与已有函数尽量复用：

- `编辑`：复用已有的 `loadTaskDraft...` / 回填逻辑
- `删除`：复用已有删除草稿逻辑
- `测试`：新增“按草稿执行”入口，或复用当前工作台执行能力
- `创建周期任务`：新增一个跳转并预填周期任务编辑器的行为

## 8.3 周期任务预填

建议以页面状态变量的方式传递当前待创建调度的来源任务，例如：

- 设置一个全局临时状态
- 切换到 `jobs` view
- 打开调度编辑器
- 自动填入 `target_type / target_id`

本轮不强制引入复杂路由参数。

---

## 9. 错误处理与可用性要求

### 9.1 测试失败

若左侧任务的测试失败：

- toast 提示失败
- 错误详情必须写入右侧 `执行输出`

### 9.2 删除失败

- toast 提示失败
- 不清空当前选中状态

### 9.3 创建周期任务跳转失败

- 若目标 view 或编辑器初始化失败，必须 toast 提示
- 不应静默失败

### 9.4 空状态

当没有任务草稿时：

- 左侧显示空状态说明
- 引导用户在右侧创建第一个任务草稿

---

## 10. 验收标准

以下标准全部满足，视为本设计完成：

1. `飞连API任务` 页中不再显示 `模板入口`
2. 左侧出现真实 `任务列表`
3. 列表数据来自 `task-drafts`
4. 每条任务都有：
   - 测试
   - 创建周期任务
   - 编辑
   - 删除
5. 点击 `编辑` 能把任务回填到右侧工作台
6. 点击 `测试` 能把结果写到右侧执行输出
7. 点击 `创建周期任务` 能跳转到 `飞连周期任务-新建调度` 并预填当前任务字段
8. 点击 `删除` 能删除任务并处理当前选中态

---

## 11. 风险与注意事项

### 11.1 列表项信息密度

左侧列表要避免把所有字段都堆进去，建议控制在：

- 名称
- ID
- mode
- template_id

足够支持辨识即可。

### 11.2 执行结果归属

左侧列表触发的 `测试` 结果仍然写入右侧 `执行输出`，这样不会再引入第三套输出区，避免认知负担升级。

### 11.3 周期任务创建行为

本轮按你确认的方式：

- 不做“一键直接创建”
- 而是“跳转到新建调度并预填”

这样可以避免误创建调度任务。
