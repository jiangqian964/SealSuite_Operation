# API 工具箱 / Jobs / 复杂任务 页面重构设计稿

日期：2026-06-04  
范围：重新定义 API 工具箱、Jobs、复杂任务 三个模块的职责边界与页面结构

---

## 1. 背景

当前系统中：
- API 工具箱主要负责模板管理、单次请求调试
- Jobs 既承担调度，又承担部分任务定义
- 缺少面向“复杂任务 / 工作流 / 智能化输出”的独立模块

随着需求演进，现有结构存在几个问题：
1. API 工具箱与 Jobs 职责边界不清
2. Jobs 中仍出现任务参数输入，导致调度层和任务定义层耦合
3. 缺少复杂任务编排能力，无法支撑飞连 API 查询、数据处理、大模型调用、结构化输出等复合流程

因此需要重新设计三大模块：
- **API 工具箱**
- **Jobs**
- **复杂任务**

---

## 2. 设计目标

### 2.1 目标
- API 工具箱成为“任务定义工作台”
- Jobs 成为“调度中心”
- 新增“复杂任务”页面，承载多步骤任务编排与未来 Agent 能力

### 2.2 非目标（当前阶段）
- 当前阶段不直接实现完全自主决策型 Agent
- 不在第一阶段中实现全量自动工作流生成
- 不在第一阶段中做复杂权限系统与多租户隔离

---

## 3. 三大模块职责重构

### 3.1 API 工具箱
重新定位为：
**定义任务内容的工作台**

负责：
- 定义飞连 API 请求
- 配置请求参数
- 配置数据处理逻辑
- 配置大模型调用逻辑
- 配置输出结构
- 单次测试整条链路
- 保存为“任务草稿”

一句话理解：
**API 工具箱负责“做什么、怎么做”**

---

### 3.2 Jobs
重新定位为：
**任务调度中心**

负责：
- 选择一个任务草稿或复杂任务
- 配置开始时间
- 配置结束时间
- 配置执行周期
- 配置执行间隔
- 配置启停状态
- 查看最近一次执行结果

Jobs 不再负责：
- 重新填写完整 API 请求结构
- 重复填写复杂数据处理逻辑
- 重新配置大模型调用逻辑

一句话理解：
**Jobs 只负责“什么时候执行”**

---

### 3.3 复杂任务
新增独立模块，建议命名为：
**复杂任务**

负责：
- 多步骤工作流编排
- 飞连 API 查询
- 数据处理
- 大模型调用
- 结构化结果输出
- 未来扩展 Agent 自主能力

一句话理解：
**复杂任务负责“复杂链路与智能处理”**

---

## 4. 新的信息架构

建议导航调整为：
1. Dashboard
2. 连接设置
3. API 工具箱
4. Jobs
5. 复杂任务

各模块职责：
- `API 工具箱`：定义单接口或轻量任务内容
- `Jobs`：绑定时间计划
- `复杂任务`：定义多步骤任务链路与智能处理能力

---

## 5. 核心对象模型

## 5.1 Template
表示单个 API 请求定义。

字段示意：
- `id`
- `name`
- `method`
- `path`
- `query_schema`
- `path_params_schema`
- `body_schema`

用途：
- API 工具箱调用
- 复杂任务中的 API 步骤复用

---

## 5.2 Task Draft
这是重构后最重要的新对象。

它由 API 工具箱产出，表示：
**一个已经定义好执行逻辑、但尚未绑定调度的任务草稿**

建议字段：
- `id`
- `name`
- `mode`
- `source_template_id`
- `input_config`
- `transform_config`
- `llm_config`
- `output_config`

其中 `mode` 可以是：
- `api_only`
- `api_plus_process`
- `api_plus_llm`
- `workflow`

用途：
- 给 Jobs 绑定时间计划
- 给复杂任务作为基础节点复用

---

## 5.3 Job Schedule
由 Jobs 模块管理。

建议字段：
- `id`
- `draft_id`
- `enabled`
- `start_at`
- `end_at`
- `schedule_type`
- `cron`
- `interval`
- `timezone`

用途：
- 只负责何时执行哪个草稿

---

## 5.4 Complex Task / Workflow
由复杂任务模块管理。

建议字段：
- `id`
- `name`
- `goal`
- `steps`
- `execution_mode`

其中 `steps` 里每个步骤类型可能为：
- `api_call`
- `data_transform`
- `llm_inference`
- `condition`
- `output`

`execution_mode` 可为：
- `manual`
- `scheduled`
- `agent_assisted`

用途：
- 表示一个多步骤工作流
- 后续可挂载 Agent 能力

---

## 6. 典型工作流

### 6.1 标准周期任务
适用：单接口查询 / 单接口写入类任务

流程：
1. 在 API 工具箱中定义任务草稿
2. 单次测试成功
3. 保存为任务草稿
4. 在 Jobs 中选择该草稿
5. 配开始时间 / 结束时间 / 周期 / 间隔
6. 启用任务

---

### 6.2 复杂分析任务
适用：多步骤查询、数据处理、总结输出

流程：
1. 打开复杂任务页面
2. 编排步骤：
   - 飞连 API 查询
   - 数据筛选 / 聚合
   - 大模型调用
   - 输出结果
3. 手动运行验证
4. 保存为复杂任务
5. 如需周期执行，再去 Jobs 绑定调度

---

### 6.3 未来 Agent 模式
适用：目标驱动型智能任务

流程：
1. 在复杂任务页面输入目标
2. 系统生成初始工作流草稿
3. 用户检查和修正
4. 保存
5. 如需定时运行，则去 Jobs 绑定调度

---

## 7. 页面设计

## 7.1 API 工具箱

### 新职责
从“接口调试器”升级为“任务定义工作台”

### 页面内容
- 模板选择 / 请求结构配置
- 输入参数配置
- 数据处理配置
- LLM 调用配置
- 输出格式配置
- 单次测试运行
- 保存为任务草稿

### 输出结果
- 原始接口响应
- 处理中间结果
- 模型输出结果
- 最终摘要 / 结果

---

## 7.2 Jobs

### 新职责
从“任务配置 + 调度混合页”变成“纯调度中心”

### 页面内容
- 任务草稿选择器
- 开始时间
- 结束时间
- cron / interval 配置
- 启停
- 最近一次运行结果

### 页面原则
- 不再重复录入复杂 API 参数
- 不再重复录入处理逻辑
- 只聚焦计划与执行状态

---

## 7.3 复杂任务

### v1：工作流编排版
页面结构建议：
- 左侧：复杂任务列表
- 中间：步骤编排区
- 右侧：当前步骤配置区
- 底部：运行结果区

支持步骤：
- `飞连 API 查询`
- `数据处理`
- `大模型调用`
- `输出`

### v2：Agent 增强版
在 v1 基础上增加：
- 输入目标
- 自动生成工作流草稿
- 自动推荐模板
- 自动生成总结 Prompt
- 自动建议输出格式

---

## 8. 建议实现顺序

### 第一阶段
1. 重构 API 工具箱：
   - 定义任务内容
   - 单次测试
   - 保存为任务草稿

2. 重构 Jobs：
   - 只绑定时间计划
   - 不再承担复杂任务定义

3. 新增复杂任务页面：
   - 工作流编排版
   - 支持 API / 处理 / LLM / 输出四类步骤

### 第二阶段
1. 在复杂任务页面加入 Agent 增强能力
2. 自动生成工作流草稿
3. 智能推荐模板和输出样式

---

## 9. 当前阶段建议边界

### 第一阶段必须实现
- API 工具箱产出任务草稿
- Jobs 绑定调度
- 复杂任务页面支持工作流编排

### 第一阶段不实现
- 完全自主决策型 Agent
- 复杂多分支自动推理
- 高级权限隔离

---

## 10. 验收标准（DoD）

1. API 工具箱可以保存任务草稿  
2. Jobs 不再重复录入复杂 API 参数  
3. Jobs 支持绑定任务草稿并配置周期 / 时间范围  
4. 新增复杂任务页面  
5. 复杂任务页面支持 API 查询、数据处理、LLM 调用、输出四类步骤  
6. 复杂任务可以手动运行并查看结果  
7. 复杂任务可被 Jobs 调度
