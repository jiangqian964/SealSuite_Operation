# 2026-06-06 — 连接设置重构为 API 配置中心设计说明

## 1. 背景

当前 `连接设置` 页面主要由三部分构成：

- 飞连连接配置表单
- LLM 双模型角色配置表单
- 最近启用的飞连连接列表

这个结构可以完成基本配置，但存在几个明显问题：

1. **信息组织按“表单”而不是按“配置对象”组织**
   - 左右关系不清晰
   - 用户很难形成“我在管理哪些 API 配置”的心智模型

2. **飞连连接有历史记录，但 LLM 配置没有历史配置中心**
   - 飞连连接可以看到最近启用记录
   - LLM 只有当前配置，没有“配置集列表”
   - 这导致左右能力严重不对称

3. **当前页更像“配置堆叠页”，不像“API 配置中心”**
   - 不利于多环境、多模型、多套配置的长期维护

因此，本次改版要把 `连接设置` 升级为一个统一的 **API 配置中心**。

---

## 2. 改版目标

本次改版目标如下：

1. 将 `连接设置` 页面重构为 **左右两个大板块**
2. 左侧改为“最近启用 API 列表区”
3. 左侧上下分为两个子模块：
   - `飞连_API`
   - `LLM_API`
4. 每个子模块都展示最近录入的 API 配置信息
5. 当前实际在用的配置以 `ACTIVE` 标签高亮
6. 支持删除已配置 API 信息
7. 右侧改为统一的 `API 详情工作台`
8. 右侧支持：
   - 查看 API 配置详情
   - 编辑当前配置
   - 新增飞连 API 配置
   - 新增 LLM API 配置
9. 保留当前 `配置输出` 窗口，用于 API 可用性测试与保存反馈

---

## 3. 非目标

本次改版不做以下事情：

- 不改动飞连 token 获取协议
- 不改动 LLM 测试 API 的核心调用逻辑
- 不引入多页路由
- 不把“连接设置”拆成独立子页面
- 不在本轮引入复杂权限控制

---

## 4. 页面结构设计

采用你确认的最终方向：

- 左侧：API 列表区
- 右侧：API 详情 / 新增 / 编辑工作台

## 4.1 左侧：最近启用 API 列表区

左侧整体用于管理已录入配置，分成上下两个子模块：

### A. `飞连_API`

用途：

- 展示最近录入的飞连连接配置
- 标识当前正在运行时生效的配置
- 提供切换、加载、删除入口

每条记录建议展示：

- 名称
- 地址（`scheme://host:port`）
- `AccessKey ID` 脱敏摘要
- `ACTIVE` 标签（若为当前运行时配置）

每条记录的操作：

- `查看/加载`
- `设为 ACTIVE`
- `删除`

### B. `LLM_API`

按你已确认的方式，这里不采用“单角色记录”模型，而是采用：

> **配置集（planner + formatter 为一组）**

也就是左侧每条 `LLM_API` 记录代表一套完整的 LLM 配置集，而不是单独一条 planner 或 formatter 记录。

每条记录建议展示：

- 配置集名称
- Planner 的 provider / model 摘要
- Formatter 的 provider / model 摘要
- `ACTIVE` 标签（若为当前正在使用的 LLM 配置集）

每条记录的操作：

- `查看/加载`
- `设为 ACTIVE`
- `删除`

---

## 5. ACTIVE 的定义

为了避免用户误解，“ACTIVE” 的语义必须明确：

### 5.1 飞连_API 的 ACTIVE

表示：

- 当前运行时系统实际在使用的飞连连接配置

### 5.2 LLM_API 的 ACTIVE

表示：

- 当前运行时系统实际在使用的 **整套 LLM 配置集**

这套配置集应当包含：

- planner 配置
- formatter 配置

这样用户看到的是“一套生效中的 LLM 能力配置”，而不是两个分裂的角色记录。

---

## 6. 右侧：API 详情工作台

右侧是统一工作台，不再拆成多个彼此独立的大卡片。

右侧承担三类职责：

1. **查看选中配置详情**
2. **编辑当前配置**
3. **新增 API 配置**

同时保留底部的：

4. **配置输出 / 测试输出**

## 6.1 工作台状态

右侧工作台存在 3 种状态：

- `查看态`
- `编辑态`
- `新建态`

顶部建议显示当前上下文，例如：

- 当前类型：`飞连_API` / `LLM_API`
- 当前模式：`查看` / `编辑` / `新增`
- 当前状态：`ACTIVE` / `未启用`

---

## 7. 右侧：飞连_API 详情与编辑

当左侧选中 `飞连_API` 记录时，右侧展示：

- 名称
- scheme
- host
- port
- AccessKey ID
- AccessKey Secret

操作按钮建议保留：

- `测试连接`
- `保存并热更新`
- `设为 ACTIVE`
- `删除`

说明：

- `保存并热更新` 仍然是主写入动作
- `测试连接` 的结果继续写入 `配置输出`
- Secret 仍然不回显；若不覆盖则允许留空

---

## 8. 右侧：LLM_API 详情与编辑

当左侧选中 `LLM_API` 记录时，右侧展示一整套配置集详情，包括：

### Planner

- enabled
- provider
- base_url
- api_key
- model
- timeout
- temperature
- max_tokens
- thinking
- reasoning_effort
- system_prompt

### Formatter

- enabled
- provider
- base_url
- api_key
- model
- timeout
- temperature
- max_tokens
- thinking
- response_format
- system_prompt

操作按钮建议保留：

- `测试 Planner`
- `测试 Formatter`
- `保存并热更新`
- `设为 ACTIVE`
- `删除`

---

## 9. 新增 API 配置的设计

右侧工作台支持进入新增态。

建议顶部提供明确切换入口：

- `新增飞连_API`
- `新增 LLM_API`

### 9.1 新增飞连_API

进入一个空白飞连连接配置表单，字段与当前飞连连接表单一致。

### 9.2 新增 LLM_API

进入一个空白的 **LLM 配置集表单**，一次填写：

- planner
- formatter

这样与左侧 `LLM_API` 列表的“配置集”语义保持一致。

---

## 10. 配置输出区域

你要求“保留当前的配置输出窗口，用于 API 可用性测试”，因此本次不移除输出区，而是统一把它纳入右侧工作台底部。

## 10.1 飞连_API 输出

继续保留：

- 当前加载结果
- 保存反馈
- token 获取结果
- probe 结果
- `token_request_preview`

## 10.2 LLM_API 输出

继续保留：

- 当前加载结果
- 保存反馈
- Planner 测试结果
- Formatter 测试结果

设计原则：

- toast 只负责轻提示
- 完整结果必须落在输出区

---

## 11. 删除规则

删除能力必须支持，但要有安全保护。

### 11.1 删除飞连_API

建议规则：

- 非 ACTIVE 配置：允许删除
- ACTIVE 配置：默认不允许直接删除

用户必须先切换到其他配置，再删除当前 ACTIVE 项。

### 11.2 删除 LLM_API

同理：

- 非 ACTIVE 配置集：允许删除
- ACTIVE 配置集：默认不允许直接删除

这样可以避免运行时失配。

---

## 12. 数据模型要求

这次改版不只是 UI 改动，还涉及数据能力升级。

## 12.1 飞连_API

当前已有能力：

- 历史连接列表
- ACTIVE 切换

缺失能力：

- 删除连接配置

## 12.2 LLM_API

当前缺失完整“配置集中心”，因此需要补齐：

- LLM 配置集历史存储
- 配置集列表接口
- ACTIVE 切换能力
- 删除能力
- 从配置集加载到右侧工作台的能力

换句话说，本轮要把 LLM 从“当前配置编辑页”升级为“配置集管理”。

---

## 13. 推荐前端实现方式

## 13.1 页面布局

当前 `view-connection` 可从“多卡片纵向堆叠”改为：

- 左列：双列表
- 右列：统一工作台

推荐比例：

- 左列：`0.9fr`
- 右列：`1.4fr`

## 13.2 左列数据结构

左列分别缓存：

- `__connListCache`
- `__llmConfigSetCache`

并分别维护：

- 当前选中飞连配置 ID
- 当前选中 LLM 配置集 ID

## 13.3 右列工作台状态

建议维护统一状态：

- 当前类型：`connection` / `llm_config_set`
- 当前模式：`view` / `edit` / `create`
- 当前对象 ID

这样页面逻辑会比现在的“多块并列、按钮分散”更可控。

## 14. 用户操作路径

### 14.1 查看已有飞连配置

1. 进入 `连接设置`
2. 左侧选择 `飞连_API`
3. 点击某条配置
4. 右侧查看详情

### 14.2 新增飞连配置

1. 进入 `连接设置`
2. 右侧点击 `新增飞连_API`
3. 填写配置
4. 测试连接
5. 保存并热更新

### 14.3 新增 LLM 配置集

1. 进入 `连接设置`
2. 右侧点击 `新增 LLM_API`
3. 填写 planner + formatter
4. 测试 Planner / Formatter
5. 保存并热更新

### 14.4 切换 ACTIVE

1. 在左侧找到目标配置
2. 点击 `设为 ACTIVE`
3. 右侧与输出区显示切换反馈

### 14.5 删除配置

1. 在左侧找到非 ACTIVE 配置
2. 点击 `删除`
3. 二次确认
4. 列表刷新

## 15. 验收标准

以下条件全部满足，视为本次设计完成：

1. `连接设置` 页面变成左右双栏
2. 左侧存在两个子模块：
   - `飞连_API`
   - `LLM_API`
3. 两个子模块都能显示历史配置列表
4. 当前实际在用配置有 `ACTIVE` 标签
5. 两类配置都支持删除非 ACTIVE 项
6. 右侧可查看选中项详情
7. 右侧可新增飞连 API 配置
8. 右侧可新增 LLM API 配置集
9. 保留并统一展示配置输出 / 测试输出

## 16. 风险与注意事项

### 16.1 这是 UI 改版 + 数据能力升级，不只是换布局

尤其 `LLM_API` 的历史配置集能力当前并不存在，因此本轮一定要包含：

- 后端接口
- 存储结构
- ACTIVE 切换逻辑

### 16.2 不建议允许直接删除 ACTIVE 项

否则运行时会出现“当前页面显示存在配置，但系统实际引用对象已被删掉”的问题。

### 16.3 `LLM_API` 必须按“配置集”管理

这是你已确认的方向。  
如果后续改成“单角色记录”，会导致：

- 左侧列表噪声过大
- ACTIVE 逻辑复杂化
- 右侧详情与新增表单变得不一致

因此本轮设计固定采用：

> `LLM_API = planner + formatter 一组配置集`
